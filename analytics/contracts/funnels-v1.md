# Site Pulse 统一漏斗配置 v1

本规范是四个产品开发会话和站点脉搏的公共入口。每次修改埋点、漏斗或发布前读取本规范。它统一可发布配置与发布检查，不会自动重写任何已开始会话的上下文，也不从 GA4 Explore 反向枚举定义。

## 唯一可编辑配置与交付

- 产品仅维护 `analytics/funnels.json`；构建时校验并复制同一文件为 `public/.well-known/site-pulse.json`，生产地址为 `https://<hostname>/.well-known/site-pulse.json`。不要维护第二份手写副本。
- 配置字段和限制以 [JSON Schema](https://site-pulse-nine-tau.vercel.app/contracts/funnels-v1.schema.json) 为准。`schemaVersion=1`，`hostname` 必须为本产品正式主机名；`revision` 在配置变动时更新；`qaPolicy` 固定为 `no-collection-for-tests-v1`。
- `events` 列出受产品当前埋点合同支持的事件；每步的 `event` 必须在此表中。同一步多个候选事件用 `|` 表示有限 OR 集合（最多 10 个），每个候选都须存在；不是任意正则。漏斗 `id` 稳定且唯一；修改名称/步骤保持同一个 id，新流程用新 id。
- 保留所有已确认的步骤、过滤条件、间隔限制以及创建/编辑区分。公开配置仅包含名称、步骤、条件和来源，不能放令牌、密码、邮箱、用户/订单数据或统计结果。
- 如保留 `source`，其 `url` 为 HTTPS 配置/GA4 参考地址，`note` 清楚说明是产品发布配置、GA4 网页独立改动不自动带入。平台对缺省来源自动使用本产品 manifest URL。

## 开发与发布检查

- 修改埋点或漏斗时同步检查本产品配置。不能从新事件名自动推断业务顺序，新增业务流程需明确设计步骤。
- 本地/CI 校验公共 JSON Schema（可以缓存最近一次已验证的同版本 schema 支持离线开发；CI 必须核对线上规范可用且与缓存一致，不可静默使用未知版本）。规范升级不通过聊天反复复制，以公共入口和版本为准。
- 额外检查：hostname 精确匹配、漏斗 id 与 events 无重复、每个候选事件属于真实埋点合同；保证源码配置与发布文件字节一致。配置不合法、缺失、引用不存在事件、QA 声明缺失时检查失败。
- 构建和 CI 必须执行这些检查，不能只依赖 AGENTS.md。保留已有测试流量采集前拦截及离线测试；不能为验证 manifest 发送任何真实 GA4 事件。
- 自动化生产验收在导航前拦截 SDK、collect、beacon、batch、离开页面采集；工具无法保证拦截时使用本地/预览。手工生产测试用 `?analytics_test=1`；显式退出为 `?analytics_test=0`，不能覆盖自动化排除。按域名保存 QA；历史未标记流量不猜测删除。

## 聚合平台行为

站点脉搏只从已配置的正式域名固定路径读取，自动查询缓存最长 10 分钟，站内刷新可强制重取。返回新定义后保留用户自定义覆盖。请求失败、格式/hostname/事件校验失败时保留当前进程最近可用配置；冷启动时回退随平台发布的配置，并明确提示失败。进程缓存不是持久数据库，不能承诺跨冷启动保存最近版本。

平台始终在查询时附加可信的精确 hostname 与已确认 QA 排除条件，远端配置不能绕过它们。统计仍来自 Google API，配置同步不代表已有真实新事件。
