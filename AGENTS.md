# Project instructions

## Analytics test isolation

- Production development/acceptance visits must enter through `?analytics_test=1` (also accepts `?qa=1`). Capture QA mode before consent in both sessionStorage and localStorage; preserve it through navigation and new same-origin tabs. A normal manual browser uses `?analytics_test=0` to explicitly reset it. Each domain has independent storage and must be marked separately. An explicit reset never overrides `navigator.webdriver=true`.
- QA and automated visits must never load the GA4 SDK or send any events, including page views, tool/learning actions, checkout or purchases. Preserve normal visitors' existing consent, event names and business behavior. Local and preview origins must not collect into production GA4.
- Before every automated production navigation, intercept the Google analytics SDK and all collection transports/endpoints, including collect, g/collect, beacon, batches and unload requests. Do not rely only on webdriver detection or a page flag. When the available tool cannot intercept transport, use local/preview instead.
- Test normal-visitor event contracts only in an offline fixture with transport interception installed before simulating a human browser. Never send synthetic events to real Google Analytics, and never use collector HTTP 204 as automated acceptance evidence. Verify zero QA SDK/collection, entry before consent, cross-page/tab persistence and explicit reset. Do not relax production collection to make old tests pass.
- Historical unmarked tests cannot be reliably identified. Do not infer or delete them from country, device, low counts or entire dates. Preserve documented legacy exclusions. The analytics aggregation platform excludes known QA in overview and all funnels; do not activate GA4 permanent data filters without separate authorization.
- Before any future feature-branch release, include and retain main's isolation implementation and offline acceptance fixtures from PR #16 (main merge `8d5e385394af5dfc24dc27e2ae6f6d4cf5815fe1`): `src/lib/analytics-traffic.ts`, `src/scripts/analytics.ts`, `tests/e2e/analytics-fixture.ts` and their related tests. An old branch must not revert the live isolation fix. Any branch missing this fix must not be released until the isolation code and offline tests are included and verified.
- Rule synchronization alone does not authorize production changes, merges, deployment, audio, payments, database or credential operations. Preserve existing work and branch boundaries; do not reset, switch branches or blindly merge all of main. Previously authorized tasks retain their original scope and release boundaries.
